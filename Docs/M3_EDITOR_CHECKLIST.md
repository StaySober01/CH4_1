# M3 숫자 제출·판정 검증

**사용자 검증 완료**. 사용자의 '모두 검증 완료' 보고를 근거로 빌드/규칙 테스트/위젯 연결/PIE 완료를 기록한다. 개별 실행 로그는 별도 수집하지 않았고 Codex가 실행한 결과가 아니다. 아래 절차는 회귀 검증에 사용할 수 있다.

## 1. 빌드 후 기존 위젯 확장

1. 에디터를 닫고 Development Editor / Win64 빌드한다. 새 USTRUCT/라이브러리/RPC/바인딩이 있으므로 정식 빌드로 확인한다.
2. 에디터에서 기존 WBP_NBChat을 연다. 새 BindWidget 두 개가 아직 없어서 위젯 Compile 오류가 나면 아래 작업으로 연결한다.
3. 기존 채팅 입력줄 아래에 Horizontal Box를 추가한다. Vertical Box Slot은 Auto로 설정한다.
4. 다음 위젯을 배치하고 이름/타입/Is Variable을 확인한다.

| 이름 | 위젯 타입 | 권장 설정 |
| --- | --- | --- |
| GuessInput | Editable Text Box | Horizontal Box Slot: Fill, Hint Text: 중복 없는 1~9 숫자 3자리 |
| GuessButton | Button | Slot: Auto, 내부 Text: 숫자 제출 |

기존 ChatInput/SendButton/ChatScrollBox/ChatHistoryText는 유지한다. 이벤트 그래프에 추가 전송 이벤트를 만들지 않는다. C++이 Enter와 버튼을 연결한다. GuessInput에 숫자 전용 필터나 자동 공백 제거는 넣지 않는다. 서버의 잘못된 입력 검증을 직접 확인할 수 있어야 한다.

5. WBP_NBChat을 Compile/Save한다. BP_NBPlayerController의 Chat Widget Class는 기존 WBP_NBChat을 그대로 사용한다.

## 2. 계산 자동화 테스트 (사용자 실행)

PIE를 종료한 에디터의 Session Frontend → Automation에서 `NB.Rules`를 검색하여 세 테스트를 실행한다. 메뉴 위치를 찾기 어려우면 에디터 Output Log 명령 입력란에서 `Automation RunTests NB.Rules`로 실행하고 결과 로그를 확인할 수 있다.

| 테스트 | 검증 내용 |
| --- | --- |
| NB.Rules.InputValidation | 길이/문자/0/중복/공백/전각 숫자 오류, 성공 시 이전 오류 초기화 |
| NB.Rules.GuessEvaluation | 정답 386 기준 OUT/S/B 사례, 잘못된 정답·입력 실패, 결과 초기화 |
| NB.Rules.AllValidNumbers | 가능한 504개 숫자 모두 허용, 자기 비교는 모두 3S0B |

테스트에는 정답 386을 직접 전달하므로 실제 게임 정답을 고정하거나 소스코드를 수정할 필요가 없다. 테스트는 규칙 계산만 검증하며 RPC/UI 성공을 보장하지 않는다.

## 3. 2 Player PIE

M2와 같이 Listen Server + 원격 Client 2인으로 실행한다. Output Log에서 `Server answer=`를 찾아 이번 PIE 정답을 확인한다. 예: 정답 ABC에 대해 다음 입력을 양쪽에서 번갈아 시도한다. A/B/C는 각각 서로 다른 실제 숫자를 뜻한다.

| 입력/동작 | 기대 결과 |
| --- | --- |
| 숫자 입력창에 ABC 그대로 제출 | 양쪽에 `[숫자] Player N: ABC → 3S0B` 한 번씩 |
| 숫자 입력창에 BCA 제출 | 0S3B |
| 숫자 입력창에 ACB 제출 | 1S2B |
| 정답에 없는 서로 다른 숫자 3개 제출 | OUT |
| 숫자 입력창에 12 / 1234 / 빈 문자열 | 제출자에게만 3자리 안내 |
| 112 / 121 / 122 | 제출자에게만 중복 금지 안내 |
| 012 / abc / 1a3 / １２３ | 제출자에게만 1~9 안내 |
| 공백을 포함한 입력 | 오류 안내, 자동으로 공백을 지우고 판정하지 않음 |
| 일반 채팅창에 123 / abc | 기존 채팅 그대로, 숫자 판정 없음 |
| 숫자 입력창에서 Enter와 제출 버튼 각각 사용 | 한 동작에 결과 한 번, 입력창 비움 및 숫자 입력 포커스 유지 |
| 같은 유효 숫자를 양쪽에서 제출 | 동일한 정답에 대해 같은 판정 |

정답이 386인 경우 참고: 127→OUT, 167→0S1B, 123→0S1B, 368→1S2B, 638→0S3B, 381→2S0B, 386→3S0B.

잘못된 입력은 상대 화면에 표시되지 않아야 한다. 반복 제출로 숫자 판정이 누적되거나 일반 채팅이 두 번 전송되지 않는지도 확인한다.

## 4. 생성과 범위 확인

- PIE를 여러 번 종료/시작하여 정답 로그가 매 실행 한 번 나오고, 항상 1~9의 중복 없는 3자리인지 확인한다. 우연히 같은 정답이 다시 나오는 것은 정상이다.
- 정답은 개발 서버 로그만 출력한다. 한 프로세스 PIE의 Output Log는 서버/클라이언트 로그를 합쳐 보여줄 수 있으므로 로그창에 보인다는 사실이 클라이언트로 정답이 복제되었다는 뜻은 아니다.
- 화면에는 입력과 S/B 결과만 표시한다. 정답을 그대로 제출했을 때 해당 입력이 보이는 것은 정상이다.
- M3는 PIE 시작 시 정답 생성과 판정만 구현한다. 아직 3회 제한, 승리 공지, 자동 리셋, 2명 대기, 턴 제한이 없다. 3S 뒤에도 계속 입력되는 것이 이번 단계의 기대 동작이다.

공유할 결과: 빌드 성공 여부, 세 규칙 테스트 결과, 양쪽 숫자 판정·개인 오류 안내·일반 채팅 회귀 결과. 오류가 있으면 최초 오류/관련 LogNB를 함께 전달한다.
